# エンジン要件定義

方式は ADR-0003・0004、仕様は `docs/specifications/engine.md`。

## REQ-ENG-001: ノート単位のエンジン選択

| 項目 | 内容 |
|------|------|
| ID | REQ-ENG-001 |
| 優先度 | Must |
| ステータス | Draft |

### 説明

ノートごとに合成エンジン（AI / Classic / Spectral / 既定に従う）を選べる。既定はアプリ設定のエンジンに従う。
エンジンが切り替わる境界は短いクロスフェードでつなぐ。

### 受入条件

- [ ] 隣り合うノートで別のエンジンを選んでも、境界でクリックやノイズが出ない
- [ ] エンジンの選択がプロジェクトと ARA ドキュメントに保存され、再読み込みで戻る
- [ ] 既存プロジェクト（エンジンがプロジェクト単位のもの）を読み込める

### 依存要件

- なし

## REQ-ENG-002: スペクトル包絡エンジン

| 項目 | 内容 |
|------|------|
| ID | REQ-ENG-002 |
| 優先度 | Should |
| ステータス | Draft |

### 説明

STFT でピッチを変え、推定したスペクトル包絡を元に戻してフォルマントを保つエンジン（Vovious に近い方式）。
`DspSynthesisRequest` を受け取り、PSOLA と同じ範囲のサンプルを返す。

### 受入条件

- [ ] 評価セットで、PSOLA より自然と判定される場面がある（判定方法は M4 の計画で決める）
- [ ] 上の条件を満たさない場合、エンジンを既定の選択肢から外す判断を ADR に記録する
- [ ] 比率 1.0 で原音との差が十分小さい

### 依存要件

- REQ-ENG-001

## REQ-ENG-003: 包絡推定器の差し替え

| 項目 | 内容 |
|------|------|
| ID | REQ-ENG-003 |
| 優先度 | Should |
| ステータス | Draft |

### 説明

包絡推定を差し替えられる形にする。最初は古典的な手法（True Envelope など）で作り、ニューラル推定器を後から追加できるようにする。

### 受入条件

- [ ] 推定器の差し替えが、エンジン本体を変えずにできる
- [ ] 推定器ごとの出力を同じ入力で比べるテストがある

### 依存要件

- REQ-ENG-002

## REQ-ENG-004: 自動ルーティング

| 項目 | 内容 |
|------|------|
| ID | REQ-ENG-004 |
| 優先度 | Should |
| ステータス | Draft |

### 説明

「既定に従う」ノートについて、補正量・遷移部かどうか・有声音の安定度から、区間ごとにエンジンを自動で選ぶ。
どの区間がどのエンジンかを色で表示する。

### 受入条件

- [ ] 自動で選んだ結果が、ノート単位の手動選択で上書きできる
- [ ] 区間ごとのエンジンがピアノロールで確認できる
- [ ] 同じ入力からは常に同じ選択になる

### 依存要件

- REQ-ENG-001, REQ-ENG-002
